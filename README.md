# React 100本ノック #006｜天気検索アプリ

React 100本ノックの6本目です。

今回は、外部APIから天気情報を取得して画面に表示する「天気検索アプリ」を作成しました。

#005まではReactの中でデータを管理していましたが、今回はReactの外にあるAPIからデータを取得する処理に挑戦しました。

---

## 🎯 目的

今回の課題では、以下を理解することを目的としています。

- APIとは何かを理解する
- ReactからAPIにアクセスする方法を理解する
- `fetch`を使ったデータ取得を理解する
- `async / await`を使った非同期処理を理解する
- APIから取得したデータを`useState`で管理する
- API通信中の状態を管理する
- API通信でエラーが発生した場合の処理を理解する
- APIから取得したデータを画面に表示する

## 💡 実装した機能

### 1. 都市名の入力

都市名を入力できます。

```text
[ 東京 ]

[ 天気を検索 ]
```

---

### 2. 天気情報の取得

「天気を検索」ボタンを押すと、APIから天気情報を取得します。

処理の流れは以下のようになっています。

```text
都市名を入力
↓
都市検索API
↓
緯度・経度を取得
↓
天気API
↓
天気・気温・湿度を取得
↓
画面に表示
```

---

### 3. Loading表示

API通信中は、

```text
検索中...
```

と表示します。

通信中は検索ボタンを押せないようにしています。

---

### 4. エラー処理

都市名が入力されていない場合、

```text
都市名を入力してください
```

と表示します。

都市が見つからない場合は、

```text
都市が見つかりませんでした
```

と表示します。

API通信に失敗した場合もエラーメッセージを表示します。

## 🧠 学んだこと

### useState

今回も`useState`を使用して、画面の状態を管理しました。

```tsx
const [city, setCity] = useState("");
```

`city`にユーザーが入力した都市名を保存しています。

また、

```tsx
const [weather, setWeather] = useState<Weather | null>(null);
```

でAPIから取得した天気情報を保存しています。

---

### fetch

APIからデータを取得するために`fetch`を使用しました。

```tsx
const response = await fetch(URL);
```

`fetch`を使うことで、指定したURLにアクセスしてデータを取得できます。

---

### async / await

API通信はすぐに結果が返ってくるとは限らないため、非同期処理として扱います。

```tsx
const response = await fetch(URL);
```

`await`によって、APIからの結果が返ってくるまで待ってから次の処理へ進みます。

---

### try / catch

API通信に失敗した場合に備えて、`try / catch`を使用しました。

```tsx
try {
// API通信
} catch (error) {
// エラー処理
}
```

APIが利用できなかった場合などに、ユーザーへエラーを表示できます。

---

### loading

API通信中かどうかをstateで管理しています。

```tsx
const [loading, setLoading] = useState(false);
```

API通信を開始すると、

```tsx
setLoading(true);
```

通信が終了すると、

```tsx
setLoading(false);
```

としています。

これによって、

```text
通信中
↓
検索中...
```

という表示ができます。

## 🔄 API通信の流れ

今回のアプリでは、APIを2回利用しています。

```text
① 都市名
↓
都市検索API
↓
緯度・経度
↓
② 天気API
↓
天気情報
↓
Reactのstate
↓

```

都市名だけでは天気APIから情報を取得できないため、最初に都市検索APIを使って緯度・経度を取得しています。

その後、取得した緯度・経度を天気APIに渡しています。

# 🔍 つまずいたところ

## 日本語の都市名で検索できなかった

今回、一番つまずいた部分です。

最初は、

```text
東京
```

と入力して検索すると、

```text
都市が見つかりませんでした
```

と表示されました。

しかし、

```text
Tokyo
```

と入力すると正常に検索できました。

---

## 原因

最初のコードでは、入力された都市名をそのままAPIに渡していました。

```text
東京
↓
API
↓
東京という名前で検索
↓
検索結果が取得できない
```

一方で、

```text
Tokyo
↓
API
↓
検索結果が取得できる
```

という状態でした。

また、APIのURLに指定していた、

```text
language=ja
```

は「日本語で入力された都市名を英語に変換する」という機能ではありませんでした。

そのため、`language=ja`を指定しているだけでは日本語入力を英語の都市名に変換できませんでした。

---

## 解決方法

日本語の都市名をAPIで検索できる都市名に変換するため、変換用のオブジェクトを作成しました。

```tsx
const cityMap: Record<string, string> = {
東京: "Tokyo",
大阪: "Osaka",
名古屋: "Nagoya",
福岡: "Fukuoka",
札幌: "Sapporo",
横浜: "Yokohama",
京都: "Kyoto",
神戸: "Kobe",
仙台: "Sendai",
広島: "Hiroshima",
};
```

そして、入力された都市名を検索前に変換します。

```tsx
const searchCity = cityMap[city.trim()] ?? city.trim();
```

これによって、

```text
東京
↓
Tokyo
↓
APIで検索
↓
緯度・経度を取得
↓
天気情報を取得
```

という処理ができるようになりました。

---

## `??`について

以下のコードも今回学んだポイントです。

```tsx
const searchCity = cityMap[city.trim()] ?? city.trim();
```

例えば、

```text
東京
```

の場合、

```text
cityMap["東京"]
↓
"Tokyo"
```

となります。

一方、`cityMap`に登録されていない都市の場合は、

```text
cityMap["London"]
↓
undefined
```

となるため、

```text
city.trim()
```

が使われます。

つまり、

> 変換表に存在する都市なら変換し、存在しなければ入力された値をそのまま使用する

という処理です。

## 🏐 バレーボールに例えると

今回のAPI通信をバレーボールに例えると、

```text
自分
↓
「東京の情報ください」
↓
相手に伝わらない
↓
「Tokyo」と伝える
↓
相手に伝わる
↓
情報を受け取る
↓
その情報を使ってプレーする
```

というイメージです。

`fetch`は相手に情報を取りに行く動作、

APIは情報を提供してくれる窓口、

`useState`は受け取った情報を保持しておく場所、

`cityMap`は相手に伝わる言葉へ変換する役割として考えました。

## 📚 今回の学習ポイント

今回の課題を通して、以下の流れを理解しました。

```text
ユーザー入力
↓
useState
↓
fetch
↓
API
↓
レスポンス
↓
JSON
↓
useState
↓
画面表示
```

Reactアプリの中だけでデータを扱うのではなく、

**React → 外部API → データ取得 → React → 画面表示**

という、実際のWebアプリでよく使われる流れを体験できました。

今回は、最初からすべてを理解してからコードを書くのではなく、

1. まず動くものを作る
2. 実際に動かしてみる
3. エラーや問題を確認する

5. 修正する
